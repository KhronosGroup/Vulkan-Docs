[[nv-internal-handles]]
= NV Internal Handles

This extension provides a mechanism for applications to obtain opaque
internal driver handles for certain Vulkan objects.

Layers may: intercept the commands defined by this extension.
An interceptor must: not return a wrapped handle to the application.
The returned basetype:VkInternalHandleNV value refers directly to the
implementation's internal object representation.

No special flags or creation requirements are needed to obtain internal
handles.
Any object of a supported type can: be queried.
Obtaining an internal handle does not affect the object's state or usability
through the Vulkan API.

An object's internal handle can: be obtained multiple times.
Each call returns the same handle.

If an object's state changes after its internal handle is obtained, the
handle continues to refer to the same underlying driver object, subject to
the same synchronization requirements.

[open,refpage='VkInternalHandleNV',desc='Opaque internal driver handle type',type='basetypes']
--
basetype:VkInternalHandleNV represents an opaque internal driver handle for
a Vulkan object, as returned by flink:vkGetPhysicalDeviceInternalHandleNV,
flink:vkGetDeviceInternalHandleNV, flink:vkGetQueueInternalHandleNV, or
flink:vkGetCommandBufferInternalHandleNV:

include::{generated}/api/basetypes/VkInternalHandleNV.adoc[]

basetype:VkInternalHandleNV is defined as a pointer to an incomplete
code:VkInternalObjectNV structure.
The contents and layout of the memory referenced by these handles are
implementation-defined.
Applications must: not interpret or dereference these handles.
This extension defines no Vulkan interface that consumes them.
An application must: only pass them to external APIs that accept them.
The operations performed by those external APIs are outside the scope of
this Specification.

The internal handle returned for a valid object is never `NULL`.

Each returned internal handle remains valid for the lifetime of its
corresponding Vulkan object:

  * Internal handles for a sname:VkPhysicalDevice remain valid until the
    sname:VkInstance used to enumerate that physical device is destroyed.
  * Internal handles for a sname:VkDevice remain valid until that device is
    destroyed.
  * Internal handles for a sname:VkQueue remain valid until the
    sname:VkDevice that owns the queue is destroyed.
  * Internal handles for a sname:VkCommandBuffer remain valid until that
    command buffer is freed.
    This includes freeing the command buffer explicitly with
    flink:vkFreeCommandBuffers and freeing it implicitly when its command
    pool is destroyed.

All synchronization requirements that apply to the original Vulkan handles
also apply when accessing objects through the corresponding internal
handles.
Specifically, the application must: externally synchronize access to an
object between the Vulkan API and any external API using its internal
handle.
--

[open,refpage='vkGetPhysicalDeviceInternalHandleNV',desc='Get an internal handle for a physical device',type='protos']
--
To obtain an internal handle for a physical device, call:

include::{generated}/api/protos/vkGetPhysicalDeviceInternalHandleNV.adoc[]

  * pname:physicalDevice is the physical device to query.
  * pname:pHandle is a pointer to a basetype:VkInternalHandleNV value in
    which the internal handle is returned.

[open,refpage='vkGetCommandBufferInternalHandleNV',desc='Get an internal handle for a command buffer',type='protos']
--
To obtain an internal handle for a command buffer, call:

include::{generated}/api/protos/vkGetCommandBufferInternalHandleNV.adoc[]

  * pname:commandBuffer is the command buffer to query.
  * pname:pHandle is a pointer to a basetype:VkInternalHandleNV value in
    which the internal handle is returned.

Both primary and secondary command buffers can: be queried.
A command buffer can: be queried in any state, including:

  * The <<commandbuffers-lifecycle, initial state>> (after allocation or
    reset)
  * The <<commandbuffers-lifecycle, recording state>> (between
    flink:vkBeginCommandBuffer and flink:vkEndCommandBuffer)
  * The <<commandbuffers-lifecycle, executable state>> (after recording has
    completed)
  * The <<commandbuffers-lifecycle, pending state>> (after submission)

include::{generated}/validity/protos/vkGetCommandBufferInternalHandleNV.adoc[]
